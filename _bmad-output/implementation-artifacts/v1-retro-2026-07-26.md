## The unifying finding

> **What was mechanically enforced held for all thirteen stories.
> What was left to intention drifted every time.**

- *Enforced and held:* core purity (AST guards, every module) · reuse-once (an
  explicit review guardrail; three review layers confirmed no second reconciler or
  ingest loop) · ban-safety (rate limiter + structural import guard; survived 500
  sequential requests with zero throttles).
- *Left to intention and drifted:* documentation accuracy (wrong 9 times) ·
  deferral severity (3 fired triggers, 1 false premise) · whole-system correctness
  (no full-scale run until after v1 was declared done).

The engineering instincts are sound. They were applied to **code invariants** and not
to **claims, judgments, or emergent behavior**. Every finding below is an instance.

---

## ① Overclaiming was the dominant defect class — and it is a locality failure

Nine findings across five stories. Every one is true on the designed path and false
at a boundary **the author already knew about**:

| Claim | True on | False on |
|---|---|---|
| "re-running a finished backfill is a no-op" | companies with facts | zero-fact companies, re-checked each run |
| `--refresh` "idempotent" | still-present facts | facts removed since (insert-only cannot retract) |
| recovers "corrupted or lost" | matching identity keys | key-mangled / vanished facts |
| "N re-ingested, mart re-derived" | facts landed | zero landed |
| coverage summary GREEN | full coverage | partial coverage |
| `--cik` is a flag (AC + epic + PRD + README) | — | code made it positional; the shipped example errored |

The limitation was documented *elsewhere* every time — in dev notes, or as a ledger
deferral. **The knowledge was present; it just wasn't in the same place as the claim.**
Claims are authored in prose (README, `secho` strings, ACs); caveats are authored in
notes and deferrals. Nothing forces them into one sentence.

That is why fixing instances never stopped recurrence: rewording a sentence does not
make claims and caveats meet. Story 3.3's own patch shows the general fix — it added a
`rows_landed == 0` branch so the message is **computed from what happened** rather than
templated from what was intended.

**Corollary (John):** four artifacts agreed on `--cik` and all four were wrong.
Consensus among documents is not verification.

---

## ② Adversarial review was the highest-value gate

It repeatedly found defects that tests structurally could not, several ban-relevant:

- **3.2** — a transient read error let a second run steal a *live* lease: exactly the
  double-rate condition the feature exists to prevent.
- **2.3** — a systemic store failure was laundered into per-company "gaps" while the
  run kept spending EDGAR requests and exited 0.
- **2.2** — a config-valid CIK above int32 crashed the filter; `lookback_days` had no
  ceiling (OverflowError / quarterly fan-out).
- **3.2** — no TTL ceiling: one typo could honor a dead lease indefinitely.

None were found by tests. All were found by deliberately attacking the design.
**Preserve this practice.** It is the single most effective thing v1 did.

## ③ Component coverage was mistaken for system coverage

Both skipped live smokes gave two reasons, and "already covered" was the *first*:

> 3.2: *"the coalesce path is fully offline-proven… a PII risk not worth it for
> behavior already covered."*
> 3.3: *"recover = ingest-company + map-canonical composed (both already
> live-smoked)… not worth re-proving an offline-covered composition."*

So the root cause is **not** PII avoidance (that was the tiebreaker) but the
assumption that testing the parts covers the composition. Oracle disproves it: the
failure lived in the interaction between real-world data variety and an atomic
insert. No fixture would contain that row, because fixtures contain what we thought
of — and the entire problem is that nobody imagined a filer stamping
`1900-01-01 → 2199-12-31`.

**The trend is the finding, not any single decision.** Stories 1.4/1.5/1.6 *did* run
live smokes; 3.2 and 3.3 did not. Live verification **decreased as composition
increased** — exactly backwards. Each decision was locally defensible; the direction
was wrong.

Second-order effect of the same root: because NFR-7 rightly bans live EDGAR in tests,
**happy paths were structurally hard to test and were repeatedly shipped untested** —
caught in review in 2.3, 2.4, 3.1 and 3.3. Story 2.3's `--refresh` happy path is
*still* deferred as untested.

## ④ The ledger became where judgments stopped being examined

36 open items, each carrying a severity assigned once at defer time and never
revisited. When finally checked (2026-07-25/26):

- **three** items' own stated revisit triggers had already fired unnoticed
  (schema migrations, `EdgarClient` singleton, `next_canonical_version` atomicity);
- **one** item's *premise* was outright false — the `Date` range guard, filed *low*
  and "unreachable for real SEC/XBRL data", cost 26,035 Oracle facts on the first
  full-market run;
- it presented as an ordinary explained gap ("no facts in store"), indistinguishable
  from a company that legitimately has no XBRL — so nothing looked broken. That is
  AD-1's no-failures-ledger decision working as designed, and also why it hid.

Deferrals cluster where reuse was heaviest: 2.3 (6), 3.3 (5), 3.1 and 3.2 (4 each).
Recording a deferral is not the same as managing one.

## ⑤ The audit trail is thinnest where the foundation is

Stories 1.2, 1.3 and 1.4 — schema, EDGAR client, Tier 0 landing — have **no
`Review Findings` section**. They were reviewed (their deferrals exist), but *what
those reviews caught and fixed is unrecorded; only what they chose to defer
survived*. Story 1.1 has no review record anywhere. The section first appears in 1.5.

**The least-documented review produced the only production data-loss bug in v1.**

## What went well (not consolation prizes)

- **The reuse guardrail held.** Epic 2's refinement note said build resumability once
  and have Epic 3 reuse it. Three independent review layers confirmed `catch_up`
  delegates to `backfill_universe` and `recover` composes `ingest_company` +
  `map_company` — no second reconciler, no second ingest loop. An architectural
  intention surviving contact with implementation.
- **The AD-9 pivot was clean.** Story 1.5 was reworked mid-flight from statistical
  standardization to exact standard elements, and it rendered three deferred items
  *moot* rather than adding debt. Changing course without accruing mess is rare.
- **Purity discipline never slipped** across all 13 stories, because it was
  mechanically guarded rather than merely intended.
- **Dismissals were recorded with rationale** (14 of them). Most projects lose the
  record of what was considered and rejected.
- **Ban-safety worked under real load.** 500 sequential `companyfacts` requests, zero
  throttles, zero cool-downs.

## Action items

Ordered by leverage. No effort estimates — sizes are relative.

**A1 — Render user-facing output from observed state, not templates.** (small–medium)
Generalize Story 3.3's `rows_landed == 0` fix: audit every command's success/summary
message for claims not derived from the actual result. Closes defect class ①.
*Done when:* no command can print an outcome it did not verify.

**A2 — Make a full-scale run a release gate.** (small)
Not per-story — a whole-Universe `populate` before any version is declared done.
This is the only thing that would have caught Oracle. Closes ③.
*Done when:* the release checklist requires it and records the outcome.

**A3 — Remove the PII friction that made live verification feel expensive.** (small)
Suppress or redact the edgartools identity log line that echoes the contact email, so
a live run is cheap to do and safe to paste. Removes the stated tiebreaker in ③.
*Done when:* a live command's output contains no email.

**A4 — Give deferrals a re-examination mechanism, not just a record.** (medium)
Every item already names a revisit trigger; nothing checks them. The ledger header now
*warns* that severities are unrevisited guesses — a warning is not a mechanism.
Closes ④.
*Done when:* fired triggers surface without someone deciding to go look.

**A5 — Make `Review Findings` mandatory in the story template.** (small)
Prevents recurrence of ⑤. Do **not** retro-fit 1.2–1.4; the information is gone.
*Done when:* the template includes the section and no new story lands without it.

**A6 — Refine the raw-HTTP architecture guard.** (small)
It has now fired on legitimate non-EDGAR work twice — Story 3.2 (`socket.gethostname`
→ `platform.node`) and the constituents fetch (`urllib`, exempted by path). It
protects a real invariant but cannot distinguish SEC HTTP from any HTTP, so it taxes
every legitimate need and gets worked around rather than improved.
*Done when:* the guard targets SEC access specifically.

**A7 — Fix the `status` gap-count wart.** (small, already in the ledger)
A ticker rescued by the CIK backstop still reports as an unresolved gap, so `status`
overstates the count. Currently documented in the README as a stopgap.

## Significant discoveries — v1 specs no longer describe v1

Three places where shipped behavior now contradicts a written specification. These
need reconciling before v2 planning treats them as ground truth:

1. **Story 1.2's AC-2 is falsified.** It required an element-grained resolution MV
   (`resolved_fact` + `resolved_fact_mv`). Story 1.6's Approach B superseded it and
   it has been dropped. The AC still reads as satisfied.
2. **Stories 2.3/3.1 specified Tier-0-only ingestion.** `backfill` and `catch-up` now
   derive Tier 1 inline — a deliberate change, because Tier-0-only left the screening
   views empty and made "populate" a two-step ritual.
3. **Story 1.4's `Date` premise was false.** Documented above.

## v2 preparation

There is no Epic 4 — v1 closed the roadmap. What v2 needs, in dependency order:

- **Settle the Universe semantics for "all".** Coverage and `status` are defined
  against a configured list. Extending beyond a curated index needs either ~7,992
  CIKs materialized into config or an explicit "all" concept. **A design decision,
  not plumbing — and it blocks the rest.**
- **Then choose an all-companies path.** Quick (`--all-tickers`, ~8,000 sequential
  requests — rejected for now on ban risk) versus right (bulk `companyfacts.zip`, one
  download, drops in behind the existing `BackfillStrategy` seam). The bulk path is
  blocked on the sync-only `EdgarClient.run`.
- **Schema migrations (medium, trigger already fired).** `CREATE … IF NOT EXISTS` is
  create-only. Rebuilding is currently cheap because the corpus is small and
  re-derivable; at full-market scale a wipe-and-repopulate stops being trivial, so
  this gets *harder* to defer, not easier.
- **`EdgarClient` singleton enforcement** and **`next_canonical_version` atomicity** —
  both deferred pending the lease, which landed in 3.2. Note the lease covers
  `backfill`/`catch-up`/`recover` but **not** `map-canonical`, so the latter's race
  is still open.
